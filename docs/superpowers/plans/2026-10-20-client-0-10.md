# Update pynortecgo to 0.10.0 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. In this repo the flow in `docs/way-of-working.md` §1–2 applies (implementer and task-reviewer agents, waves, worktrees).

**Goal:** the integration runs on `pynortecgo` 0.10.0, with the test factories and diagnostics expectations
fitting its models (#111).

**Architecture:** one task and one commit. The bump breaks the two test factories, which miss the new
required `started_at`, and the diagnostics field pins. The pin, the lock, the factories, the diagnostics
expectations, one new sensor test and the changelog entries therefore land together, so that the commit
passes the gates. No file under `custom_components/` changes except `manifest.json`.

**Tech Stack:** Python 3.14, Home Assistant, `pynortecgo` 0.10.0, pytest with
`pytest-homeassistant-custom-component`, mypy `--strict`, ruff, uv.

**Spec:** `docs/superpowers/specs/2026-10-20-client-0-10-design.md` (issue #111). Read it with the task: this
plan argues from it.

## Global Constraints

- **No integration code changes.** Under `custom_components/`, only the `requirements` line of
  `manifest.json` changes. Its `version` doesn't: the controller's bump step sets it later. `diagnostics.py`
  and its `TO_REDACT` stay unchanged.
- **Test files:** only `tests/conftest.py`, `tests/test_diagnostics.py` and `tests/test_sensor.py` change.
  `tests/test_sensor.py` only gains one new test. Every other test file stays byte-identical. If another
  test fails on the new client, stop and report it; don't edit that test.
- **`make_charger` and `make_completed_charge` keep their existing keyword arguments**, names and defaults.
  Each gains one new keyword, `started_at`.
- **Fake values only** (hard rules 3 and 7): `FAKE_STARTED_AT = datetime(2026, 9, 27, 9, 30, tzinfo=UTC)` and
  `FAKE_LAST_STARTED_AT = datetime(2026, 9, 25, 3, 45, tzinfo=UTC)`. Fixtures are built from `pynortecgo`
  model objects, never from raw JSON. No endpoints, headers or response shapes go in code, tests, docs or
  commit messages.
- **Never start or stop a real charge** (hard rule 2). Tests mock `pynortecgo`; nothing here runs Home
  Assistant.
- **Gates before the commit** (`CLAUDE.md` → Commands):
  - `uv run pytest -q`;
  - then `uv run ruff check && uv run ruff format --check && uv run mypy && uv run actionlint && uv run zizmor --offline .github/workflows`;
  - then the coverage gate, `uv run pytest --cov=custom_components.nortec_go --cov-report=term-missing --cov-fail-under=95`.
- **Where it runs:** in the main checkout (`<checkout>`; the dispatch gives its path), on branch
  `feat/client-0-10` (a wave of one task needs no worktree). Edit files by absolute path.
- **Commit message:** write it with the Write tool to `/tmp/client-0-10-task-1-msg.txt`, and commit with
  `git commit -F <file>`. No heredocs. End it with the co-author trailer the dispatch gives.
- **PR:** titled `fix: update pynortecgo to 0.10.0 (#111)`. The controller, not the task, runs the bump
  step and `scripts/smoke`, and puts the *Bumping `pynortecgo`* checklist results from the spec into the PR
  description.

Things the spec implies that no single test states, most likely first. Each line names what pins it.

### Task 1: Move to pynortecgo 0.10.0

**Model:** opus. It changes the mapping of `pynortecgo` models in the test fixtures and the diagnostics
expectations (§5).
**Wave:** 1

**Files:**
- Modify: `custom_components/nortec_go/manifest.json` (the `requirements` line)
- Modify: `pyproject.toml` (the `pynortecgo==` line), `uv.lock`
- Modify: `tests/conftest.py` (constants; `make_charger`; `make_completed_charge`)
- Modify: `tests/test_diagnostics.py` (`ACTIVE_CHARGE_FIELDS`, `COMPLETED_CHARGE_FIELDS`, the expected
  download in `test_diagnostics_output`)
- Modify: `tests/test_sensor.py` (one new test)
- Modify: `CHANGELOG.md` (under `## [Unreleased]`)

**Interfaces:**
- Consumes: `pynortecgo` 0.10.0's `ActiveCharge(…, started_at: datetime | None)` and
  `CompletedCharge(…, started_at: datetime, completed_at: datetime)`.
- Produces: `make_charger(…, started_at: datetime | None = FAKE_STARTED_AT)` and
  `make_completed_charge(…, started_at: datetime = FAKE_LAST_STARTED_AT)`, plus the constants
  `FAKE_STARTED_AT` and `FAKE_LAST_STARTED_AT` in `tests/conftest.py`.

- [ ] **Step 4: Fix the factories in `tests/conftest.py`**

After `FAKE_COMPLETED_AT`, add:

```python
# make_charger's open charge start
FAKE_STARTED_AT = datetime(2026, 9, 27, 9, 30, tzinfo=UTC)
# make_completed_charge's start, before FAKE_COMPLETED_AT
FAKE_LAST_STARTED_AT = datetime(2026, 9, 25, 3, 45, tzinfo=UTC)
```

In `make_charger`, add a keyword after `can_stop: bool = True,`:

```text
    started_at: datetime | None = FAKE_STARTED_AT,
```

and pass it to the `ActiveCharge(...)` after `cost=charge_cost,`:

```text
            started_at=started_at,
```

Its docstring becomes:

```text
    """Return a charger; idle and unplugged unless told otherwise.

    `started_at` may be None: the client allows an open charge with no start time.

    A charge value (`charge_kwh`, `charge_kw`, `charge_cost`) needs a `charge_state`:
    without one there is no open charge to hold it, so the call is refused.
    """
```

Change `make_completed_charge` to:

```python
def make_completed_charge(
    *,
    charge_id: str = FAKE_LAST_CHARGE_ID,
    cost: float = 42.5,
    kwh: float = 18.4,
    started_at: datetime = FAKE_LAST_STARTED_AT,
    completed_at: datetime = FAKE_COMPLETED_AT,
) -> CompletedCharge:
    """Return a completed charge with fake values; its ID differs from an open charge's."""
    return CompletedCharge(
        id=charge_id,
        cost=cost,
        kwh=kwh,
        started_at=started_at,
        completed_at=completed_at,
    )
```

- [ ] **Step 6: Add the no-start-time test to `tests/test_sensor.py`**

Put it right after `test_charge_energy_and_power_sensors`. `ENERGY` and `POWER` are the module's existing
entity-ID constants.

```python
async def test_charge_sensors_read_a_charge_without_a_start_time(
    hass: HomeAssistant,
    mock_config_entry: MockConfigEntry,
    mock_client: AsyncMock,
) -> None:
    """The client allows an open charge with no start time; the charge sensors still read it."""
    mock_client.get_charger.return_value = make_charger(
        is_connected=True,
        charge_state=ChargeState.CHARGING,
        charge_kwh=3.25,
        charge_kw=7.4,
        started_at=None,
    )
    await setup_integration(hass, mock_config_entry)

    assert _state(hass, ENERGY) == "3.25"
    assert _state(hass, POWER) == "7.4"
```

Run: `cd <checkout> && uv run pytest -q tests/test_sensor.py -k without_a_start_time`
Expected: PASS. It passes at once, because the integration doesn't read `started_at`. To see that it can
fail, change `charge_kwh=3.25` to `charge_kwh=1.0` and run it again: it should fail on `ENERGY`. Then set it
back.

- [ ] **Step 7: Add the changelog entries**

### Fixed

- The log no longer warns at every restart that the car's power-delivery state is unknown when the car is
